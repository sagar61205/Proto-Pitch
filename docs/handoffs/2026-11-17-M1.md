## Known failures and blockers

No failing tests. Open points, none blocking M2:

1. **macOS not verified.** Everything was built and tested on Linux. On Docker Desktop for
   Mac, bind-mount permissions and the preview network path behave differently. Run
   `make sandbox-images && make sandbox-test` on the owner's machine before relying on the
   sandbox; report any failure rather than relaxing the driver.
2. **Registries.** The sandbox image pins `python:3.12-slim` by digest on Docker Hub. Hub
   rate limits (HTTP 429) were hit in the development container; the build script accepts
   `PROTOPITCH_BUILD_BASE_IMAGE` to use a mirror of the same digest. `docker/Dockerfile.platform`
   takes build arguments for its four base images for the same reason.
3. **Platform steps have no hard per-step kill.** Sandbox runs are killed at their time
   limit (twice over: by the driver and by `timeout` inside the container) and jobs have a
   deadline checked between steps, but a trusted Python step that hangs is not interrupted.
   Acceptable while all platform steps are short; revisit when long platform-side steps
   appear (M2 research fetches should use their own timeouts).
4. **No login.** `LocalNoAuth` relies on the loopback binding, a Host-header allow-list and
   refusal of cross-site state-changing requests. Another user account on the same machine
   could reach the port. Matches decision D1.
5. **Document upload** on the New Project form is not present; it belongs to M2 research.
6. **Deprecation warning** from the test client's HTTP library (third-party); harmless.

Implementation notes a successor needs:

- Owner-initiated lifecycle actions exposed by the API are only archive, restore and resume.
  Pipeline transitions are made by jobs through `services.transition_project`, which
  enforces the table and consumes approvals. Do not add a generic "set status" endpoint.
- Job steps reach the platform only through `StepContext`; a step records artifacts by
  returning them in its output. Keep it that way so workers can become remote
  (ARCHITECTURE §13).
- New job types register through `register(registry)`; test-only job types are in
  `backend/tests/fixture_jobs.py`.
- Local preview (`SandboxDriver.serve`) puts the application on an internal Docker network
  and forwards one loopback port through a second container running only platform code,
  because internal networks cannot publish ports.
- Workers report liveness and sandbox capability every 10 seconds; `/api/system/status`
  prefers a live worker's report, since generated code runs where the worker runs.
- Regenerate `frontend/src/api/schema.d.ts` with `make api-types` after any API change;
  `make check` fails if it is stale.
